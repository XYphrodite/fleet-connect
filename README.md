# fleet-connect

Утилита для подключения к своим машинам, когда помнить их адреса наизусть неохота.

Список ПК лежит в CSV, `fcon` показывает его меню, вы выбираете машину и протокол —
RDP или SSH — и утилита зовёт `mstsc` или `ssh`. Список можно не вести руками:
`fcon import` вычитывает его из Tailscale.

```
  Machines   (arrows move, letters jump, Enter connects, Esc quits)
  * home  home-pc.tailnet-name.ts.net   rdp  user   в гостиной
> * gpu   gpu-rig.tailnet-name.ts.net   rdp  user   RTX 4060
  * dev   dev-box.tailnet-name.ts.net   ssh
  . nuc   100.100.10.14                 ssh  root   в гараже
```

`*` — машина в сети прямо сейчас, `.` — офлайн, `?` — её нет в тейлнете (статус читается
из `tailscale status`; без Tailscale колонка просто не появляется).

## Установка

```powershell
irm https://raw.githubusercontent.com/XYphrodite/fleet-connect/master/install.ps1 | iex
```

Права администратора не нужны: это машина, *с которой* вы подключаетесь. Установщик
кладёт `fleet-connect.ps1` и шим `fcon.cmd` в `%LOCALAPPDATA%\Programs\fleet-connect` и
добавляет папку в PATH. Та же команда обновляет утилиту — список машин не трогается.

Скрипт намеренно называется не `fcon.ps1`: PowerShell находит на PATH `.ps1` раньше
одноимённого `.cmd`, и тогда `fcon` запускал бы скрипт напрямую — а политика выполнения
`Restricted`, с которой Windows приезжает с завода, это запретит. Пока под именем `fcon`
отзывается только `.cmd`, каждый запуск идёт через `-ExecutionPolicy Bypass`.

## Сборка (.NET 10)

Начиная с этой версии `fcon` — это single-file exe на .NET 10, исходники в
`src/fcon`. CSV, CLI, меню и коды возврата сохранены 1-в-1 с PowerShell-версией
(`fleet-connect.ps1` оставлена в репозитории как референс).

```powershell
# разработка (нужен .NET 10 SDK)
dotnet build src/fcon

# релизный exe без требования рантайма на клиенте (self-contained, ~70 MiB)
dotnet publish src/fcon -c Release -r win-x64 --self-contained
# -> src/fcon/bin/Release/net10.0-windows/win-x64/publish/fcon.exe

# framework-dependent (нужен .NET 10 runtime, ~0.2 MiB)
dotnet publish src/fcon -c Release -r win-x64 --self-contained false -o src/fcon/bin/Release/net10.0-windows/win-x64/publish-framework
# -> publish-framework/fcon.exe  -> переименовать в fcon-framework.exe для релиза
```

Проверка без Windows: `tests/Logic.Tests.ps1` (нужен только SDK) гоняет
настоящие исходники сквозняком — пикер, `name`, `name ssh/rdp`, `add`,
`list`, `sync --dry-run`, `import`, роутинг и все алиасы свитчей — и сверяет
выводы с кодами 0/1/2. Живые RDP/Setup/Update и интерактивный пикер
проверяются на Windows через `tests/Cli.Tests.ps1` на собранном exe.

Опубликуйте `fcon.exe` (и `fcon-framework.exe` для framework-dependent) как ассеты GitHub-релиза (тег, например `v1.0.0`):
`install.ps1` и `fcon update` забирают их с
`.../releases/latest/download/fcon.exe` (или `fcon-framework.exe` при `$env:FLEET_CONNECT_FRAMEWORK=1`, `FLEET_CONNECT_REF` выбирает тег).
SSH по-прежнему идёт через системный `ssh.exe` с наследованием консоли —
потоки не перенаправляются, иначе удалённая сессия отвязывается.

## Команды

| Команда | Что делает |
|---------|-----------|
| `fcon` | меню: выбрать машину, потом протокол |
| `fcon gpu` | сразу к машине `gpu`, её протоколом по умолчанию |
| `fcon gpu ssh` | к ней же, но по SSH |
| `fcon list` | напечатать список и выйти |
| `fcon import` | подтянуть машины из тейлнета (спросит подтверждение) |
| `fcon edit` | открыть CSV в блокноте |
| `fcon path` | напечатать, где лежит CSV |
| `fcon help` | справка |

Имя машины можно не дописывать: `fcon g` найдёт `gpu`. Точное совпадение имеет приоритет,
так что `home` не перехватывается машиной `home-backup`. Если под сокращение подходит
несколько машин — появится меню из них.

Флаги: `-NoStatus` не ходить в Tailscale за статусом, `-Yes` для `import` — записать без
вопроса (для скриптов).

Коды возврата: `0` сделано, `1` ошибка, `2` ничего не выбрано или такой машины нет.

## Список машин

`%LOCALAPPDATA%\fleet-connect\pcs.csv`, переопределяется переменной `FLEET_CONNECT_CSV`.

```csv
Name,Host,Protocol,User,SshAlias,Port,Note
home,home-pc.tailnet-name.ts.net,Rdp,user,home,,в гостиной
gpu,gpu-rig.tailnet-name.ts.net,Rdp,user,gpu,,RTX 4060
dev,dev-box.tailnet-name.ts.net,Ssh,,,,
nuc,100.100.10.14,Ssh,root,,2222,в гараже
```

| Колонка | Смысл |
|---------|-------|
| `Name` | короткое имя, его вы набираете после `fcon` |
| `Host` | адрес или DNS-имя; подставляется в команду как есть |
| `Protocol` | `Rdp` или `Ssh` — протокол по умолчанию для этой машины |
| `User` | логин для RDP, и для SSH когда не задан алиас |
| `SshAlias` | запись `Host` из `~/.ssh/config`; если заполнена, SSH идёт только через неё |
| `Port` | только если он не стандартный для протокола |
| `Note` | произвольный текст, виден в списке |

Пустые колонки — это нормально: пустой `User` даёт обычный `mstsc /v:адрес`, пустой
`Protocol` читается как `Rdp`. Опечатка в `Protocol` у одной строки не ломает весь список:
эта машина откатывается на RDP с предупреждением, остальные читаются как обычно.

## Пароли

Утилита не хранит паролей и не умеет их подставлять.

- **RDP.** Если у машины заполнен `User`, рядом со списком создаётся `.rdp`-файл с адресом
  и логином, и `mstsc` спрашивает только пароль. Всё остальное в этом файле — размер окна,
  проброс дисков, что вы настроили внутри mstsc — сохраняется: утилита переписывает
  ровно две свои строки и не трогает соседние. Если `User` пуст, файла нет вовсе, зовётся
  просто `mstsc` с адресом.
- **SSH.** Идёт через ваш обычный `ssh.exe`, то есть через `~/.ssh/config` со всеми ключами.
  Заполненный `SshAlias` используется целиком: `ssh home` — и ни логин, ни порт из CSV к
  нему не приписываются, потому что в конфиге они уже есть и спорить с ним нечему.

## Импорт из Tailscale

`fcon import` читает `tailscale status --json` и сливает результат со списком:

- Машина запоминается по **MagicDNS-имени**, если оно резолвится на этой машине, иначе по
  адресу `100.x`. Имя переживает смену адреса; адрес переживает то, что резолвер тут не
  тайлскейловский — поэтому проверяется, а не выбирается вслепую.
- Имя берётся из `DNSName`, а не собирается из `HostName`: хостнейм вроде `moscow_enjoyer`
  или `TECNO CAMON 20` в DNS-метку не помещается, и уже приведён к `moscow-enjoyer` и
  `tecno-camon-20` именно там.
- Уже известная машина **обновляется, а не дублируется** — совпадение ищется и по имени, и
  по обеим формам адреса. Ваши `User`, `SshAlias`, `Note` остаются как были.
- Телефоны и планшеты (`iOS`, `Android`) пропускаются: ни RDP, ни SSH они не слушают.
- Новой машине ставится `Ssh`, если Tailscale говорит `linux`, иначе `Rdp`.
- Перед записью показывается, что изменится, и спрашивается подтверждение. Прошлый список
  сохраняется рядом как `pcs.csv.bak`.

## Быстрая настройка нового клиента

На ПК, **с которого** нужно подключаться, запустите PowerShell под обычным пользователем:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/XYphrodite/fleet-connect/master/setup-client.ps1))) -Name home -Address home-pc.example.ts.net -User remote -SendKey
```

Замените `home`, адрес и `remote` на имя записи в fcon, Tailscale-адрес целевого ПК и его
пользователя Windows. Без параметров скрипт спросит эти три значения. Права администратора
на клиенте не нужны; нужен установленный компонент Windows OpenSSH Client.

Скрипт установит fcon, если его ещё нет, добавит запись в список и отдельный SSH-алиас,
создаст `~/.ssh/id_ed25519_fcon`. Существующий ключ используется повторно, остальные записи
сохраняются, перед изменениями создаются резервные копии. Пароль RDP вводится в окне Windows.

`-SendKey` отправляет **только открытый ключ** через Taildrop на целевой ПК. Tailscale должен
быть запущен на обоих устройствах, а между ними должен быть разрешён Taildrop. Администратор
целевого ПК должен принять ключ и добавить его в `authorized_keys`; до этого SSH-вход ещё
не настроен. Без `-SendKey` открытый ключ печатается для передачи вручную. Закрытый ключ
и пароли не отправляются.

При первом SSH-входе нужно проверить отпечаток ключа сервера. Если администратор заранее
передал открытый ключ сервера, его можно закрепить параметром:

```powershell
.\setup-client.ps1 -Name home -Address home-pc.example.ts.net -User remote -HostKey 'ssh-ed25519 BASE64_PUBLIC_HOST_KEY'
```

Скрипт не включает сервер SSH/RDP, не создаёт пользователей и не меняет брандмауэр или
правила Tailscale. Эти настройки и разрешение входа нужны на целевом ПК. Для взаимного
доступа повторите настройку клиентов и авторизацию открытых ключей в обе стороны.

После настройки:

```powershell
fcon home ssh
fcon home rdp
```

Проверка установщика без сети, в изолированных временных профилях:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/SetupClient.Tests.ps1
```

## Требования

Windows, PowerShell 5.1 или новее. Для SSH — клиент OpenSSH (`ssh.exe`); если его нет,
утилита скажет об этом и подскажет команду установки. Tailscale нужен только для `import`
и для колонки со статусом.
